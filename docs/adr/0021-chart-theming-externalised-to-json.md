# ADR-0021: Chart Theming Externalised to a Single JSON Config

- **Status:** Accepted
- **Date:** 2026-04-24
- **Deciders:** PortfoliFLOW project owner (retrofit)
- **Tags:** ui, process

---

## Context

PortfoliFLOW renders many charts (matplotlib-based, embedded in PyQt6 widgets and generated by AI tools). Visual parameters — fonts, colours, grid styles, line widths — must be consistent across the application and across export formats. If those parameters live as constants scattered through chart code, two problems follow: (a) consistency requires multi-file edits for every brand change, and (b) the planned per-client branding in the Reporting Engine (ADR-0020) becomes a code change rather than a config change.

The same constraint applies to AI-generated charts (`generate_chart` tool, ADR-0012): the theme must be applied in exactly the same way as for hand-coded widget charts.

## Decision

All chart visual parameters are read from `config/chart_theme.json` via a single helper module (`core/chart_theme.py`). Chart code — whether in widgets, modules, services/tools, or analytics — never contains hardcoded colours, fonts, or line widths. To change the look of every chart in PortfoliFLOW, edit one JSON file.

The theme JSON is versioned (`_version` field) and grouped by concern (`font`, `colours`, `line`, …) so it can be diffed and code-reviewed.

## Rationale

- A single source of truth removes drift between widgets, AI-generated charts, and any future export pipeline.
- JSON is easy to edit by non-developers (designers, brand owners), is checked into the repository, and is trivial to swap (per-environment theme files would be a near-zero-cost extension).
- Centralising the theme in `core/` (or a thin chart-helpers module) means any consumer can apply it without coupling to the GUI layer.
- The decision deliberately precedes the per-client Style Layer in the Reporting Engine (ADR-0020) — the chart theme is the simplest case of "style is data, not code".

## Alternatives Considered

- **Hardcoded constants in each chart module:** Rejected — guarantees drift over time and makes brand changes a multi-file edit.
- **Python-defined theme module (e.g., `core/chart_theme.py` with module-level constants):** Rejected as the source of truth; a Python file is reviewable but harder to swap per environment / per client and harder to edit by non-developers.
- **One matplotlib `mplstyle` file:** Rejected — `mplstyle` covers only matplotlib parameters; PortfoliFLOW's theme also influences code that decides series-palette ordering, positive/negative bar colours, etc.
- **No theming layer; inherit matplotlib defaults:** Rejected — inconsistent with the institutional look-and-feel PortfoliFLOW targets.

## Consequences

### Positive

- Brand changes are a single-file edit.
- AI-generated charts and hand-coded charts share the same look.
- The path to per-client themes (e.g., `chart_theme_<client>.json` selected at render time) is short.

### Negative

- Adding a new visual parameter requires adding it both to the JSON schema and to the consumer code.
- A malformed `chart_theme.json` can break every chart in the application; defensive loading is required.

### Neutral / Follow-ups

- Per-client / per-environment theme selection is a candidate follow-up, especially in the context of the Reporting Engine's Style Layer (ADR-0020).
- Consider validating `chart_theme.json` against a schema at startup to catch malformed entries early.

## Implementation Notes

- Theme file: `config/chart_theme.json` (versioned via `_version`).
- Loader: `core/chart_theme.py` (and / or related helpers in `core/chart_helpers.py`).
- Consumers: chart-rendering code in `gui/widgets/`, `services/tools/` (e.g., `generate_chart`), and any export pipeline.
- Documented in: `docs/architecture.md` ("Cross-cutting services — Chart theming"), `docs/chart_theme.md`.

## Compliance & Audit Relevance

- **ISO 25010 quality attributes affected:** Maintainability (modifiability — visual changes are local), Reusability (chart code is theme-agnostic).
- **Audit evidence:** `config/chart_theme.json` is checked in and versioned; absence of hardcoded colour literals in chart code is checkable by grep.

M-6 — what the states show, and the leans

Decision 1 · OP-07 — tickets dated at or before t0 (ticket #24, 2026-06-15)

  • (a) shifted preview: the panel computes with trade_date = t0 + 1 and says so in an info block above the lenses. The ticket itself is untouched; only the transformation is re-dated.
  • (b) honest no-preview: the muted state names the seam date and the two ways out (re-date, or import a later statement).
  • (c) both per ticket would be (b) with a "preview as if at t0+1" button that swaps in (a). Not drawn — it is (a) behind one click.
  • MC lean: (a). A PM proposing a back-dated ticket wants to know what it does to headroom, not that the plan world starts later. The shift is one day and is labelled. The overlay's refusal is honoured — the executor never sees a date ≤ t0.

Decision 2 · feeding statuses

  • proposed and approved render identically (#23 / #25) — same read path, and a four-eyes approver is exactly who wants this panel before approving.
  • draft (#26): the Impact button is present but the endpoint answers with the muted "propose first" state. Alternative: no button on draft rows at all. Lean: no button on draft rows — a gesture that always answers "not yet" is a gesture that should not be there. Drawn with the button so the copy exists if the operator prefers it.

Decision 3 · panel home

  • Blotter detail slot: the row is where a proposed ticket lives; the panel lands in the same cell the cancel panel uses. Two panels, one slot — Impact replaces Cancel and vice versa. Requires renaming #tx-cancel-{id} → #tx-detail-{id} in _blotter_row.html, _cancel_panel.html (Keep gesture) and test_transactions_blotter.py (P-6a, one concern).
  • Reopened composer block: a third block under the ticket, loaded lazily. Costs a composer-template touch per flow and sits below the fold.
  • Own section: a picker plus the panel. Second place to find a ticket.
  • Lean: blotter detail slot, lazily loaded on the Impact button, never on row render (a blotter of twenty tickets must not run twenty scenario assemblies).

Decision 4 · lens set v1 — what the bundle actually carries

  • The frames-aware coverage lives in services/planning_desk/scenario_results.assemble_scenario_result (a ScenarioResult: 4 KPI deltas, SAA + AnlV headroom rows, composition pair, Σ-NAV path). LimitsCoverageService.get_coverage reads the book directly and takes no frames — see the verify report.
  • SAA drift = headroom[saa] rows (utilisation, headroom, status per class). AnlV headroom = headroom[anlv] + the two KPI tiles (tightest headroom, breach count). Liquidity = KPI functional_cash_t0_plus_4q + AUM tile; the "on trade date" line is a plain sample of frames.cash_paths[currency] before/after — trivially available, not in ScenarioResult: keep or strike.
  • FX: for an order ticket the delta is zero by construction (currency mismatch is blocked at propose; both legs move in one currency). Drawn twice: as a delta block of zeros and as a one-line note. Lean: the note (or strike entirely and let the record say why). A block of zeros is a lens that never lenses.
  • "Rows unchanged" (fixed income, private markets) are shown so the reader sees the whole quota picture. Alternative: moved rows only. Keep or strike.

Decision 5 · OP-26 — previewable nav_exists_at_trade_date

  • Not drawn: it is a clause in the composer's preview (TicketService.preview), not this panel. If yes: P-6b, its own prompt — navs wiring into the composer's TicketService construction and a block row in the composer's message list. The panel is unaffected either way.

Verify-phase items that became states here (see report)

  • Costs toggle: the overlay carries one signed C for both legs; the ticket's cash effect includes fees/taxes, its value effect (units × price) does not. Either the cash leg is exact and the value leg overstated by the costs, or the reverse. The "Costs" line names the choice. Lean: C = net incl. costs — the liquidity lens is the one where a few hundred euros can flip a sign; a quota is insensitive to them. Footnote states the value overstatement.
  • Reported kind (#22) and U-NEW (#27): muted states with the fast-follow sentence, never an empty cell.
  • Book errors: DuplicateCashPositionError / PlanSeamMissingError as red service sentences, verbatim (A-7) — the same errors the Planning Desk renders as its book error strip.

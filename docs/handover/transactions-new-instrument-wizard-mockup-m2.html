Design notes — decisions this mockup proposes

  1. Draft creation gesture. The draft ticket row (and Ticket #19) is created when step 1 completes — the first Continue is the first explicit gesture, in line with M-1's persistence decision. From then on the wizard is resumable from the Blotter and survives leaving the page.
  2. AnlV gate placement. The gate is enforced at the finish, not between steps: step 2 lets you continue with the category unset (amber notice), step 4 then refuses Book now and Propose with a jump-back link, while Keep as draft stays available. Toggle "AnlV missing" above to see the refusal state. Rationale: the field the schema keeps nullable dangles only inside drafts, never past them.
  3. Propose is also gated. A proposed ticket is "complete and validated" (ADR-0128 §3), so the AnlV gate applies to Propose exactly as to Book now — only the draft may dangle. Confirm or correct.
  4. Identifier path. Resolve stores both rows (isin + figi) on the new investment and pre-fills name and currency; everything stays editable. The no-identifier card covers Spezial-AIF share classes and club deals — no fake internal code is forced at creation time.
  5. R-1 surfaced, quietly. The instrument leg reads "first purchase" in the ledger-effect block; no opening row is ever created by the wizard.
  6. Discard mid-wizard cancels the draft; the investment shell (created only at booking, not before) never needs cleanup in this design — the wizard keeps master data in the ticket until booking emits the investment. This is a schema-relevant reading: the draft carries the master data as a payload, the investment row is an emission effect. If S1 prefers creating the investment row earlier, ADR-0128 §6's orphan-shell cleanup covers it; either way the surface looks identical.
  7. Settlement block repeats M-1's single-match pattern; the other two states are identical to M-1 and not duplicated here.

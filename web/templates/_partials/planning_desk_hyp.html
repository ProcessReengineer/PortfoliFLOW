{# Hypothetical transactions — the entry surface of `insert_transaction` (mockup ④, ADR-0104 §2/§7). The block below the pacing rows: an entry form (its own partial, because the error state re-renders it alone) and the row table the parameter set projects into. **The table is rendered from the parameter set, not from the frames.** A hypothetical transaction is a parameter; the frames carry only its *effect* (the executor appends no PlanFlow for it, ADR-0104 §2). Its row and its chip in the strip are therefore two views of one thing — and the ✕ in the row is the very link the chip's ✕ carries, re-indexed by `serialise_overlay`. The **AUM column is inert**. Value and cash move by the same amount, in the same currency, on the same date, so AUM is invariant *by construction* (ADR-0104 §2) — a property of the engine, not a claim for a template to re-prove per row.

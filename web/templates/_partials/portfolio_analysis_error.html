{# FX-error state for the Portfolio Analysis section. Rendered by web/routes/portfolio_analysis.py when the ADR-0099 §4 conversion boundary raises MissingFxRateError — a foreign-currency position has no FX rate at or before a date its NAV history needs, and the system never defaults a rate to 1:1. Since ADR-0102 the frontier's inputs (the cashflow-adjusted return series and the current-portfolio NAV weights) are derived from the *converted* history, so an uncovered position would otherwise weight USD NAV against EUR NAV as if 1 = 1. Unlike the other section error states this partial carries **no section chrome**: the only FX-dependent endpoint here is the compute POST, whose response is swapped into ``#pa-chart-container`` (innerHTML). The Compute form above it stays in place, so the operator can retry once the rate is imported without reloading the area page. The exception message is passed through verbatim on purpose — MissingFxRateError is a PortfoliFlowError and therefore user-facing (web/errors.py). It names the currency and the date, which is exactly what the operator needs to extend the `FX rates` sheet. Context: error_type — exception class name. error_message — exception message. #}

{# Users section body — /admin#users (ADR-0121 §6). The tenant owner's own user list. Every form POSTs to its endpoint and swaps this whole block in place via ``hx-target="closest .pf-users"`` + ``hx-swap="outerHTML"``, so a write replaces list, form and banner with a freshly rendered set — the ADR-0112 §6 render idiom, one path for the GET and every POST. The list is grouped **active** then **deactivated**, following the Cases open/closed row idiom (``pf-case-list`` / ``pf-case-row`` / ``state``): a flat stack of framed rows, the closed group muted, a state chip per row, and ``pf-empty-state`` prose when a group is empty. Deactivation is reversible here, so the two groups live in one section rather than in two, and only the deactivated group's own action — Reactivate — is offered on its rows: a deactivated account has no session to end and passes no gate, so a reset or a re-role there would be an action without an effect to show for it. The self-targeting warnings are static template copy compared against ``is_self`` — no JS, and no confirmation dialog.

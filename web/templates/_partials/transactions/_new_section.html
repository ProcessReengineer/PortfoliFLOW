The host is what makes web/routes/areas.py a no-DB shell render: the area page ships the chooser as static markup, and the first database read happens when a tile is clicked. The host also answers Q-UX-A-5. Since P-UX-A0b an area shows one section at a time, so a composer swapped in from the Blotter — the ticket-number button targets this host — would otherwise open out of sight. Two guards, both load-bearing. `event.detail.target === this` is there because `htmx:afterSwap` bubbles and every recalculation swaps `#tx-derived` *inside* this host — only a swap of the host itself is a change of surface. The fragment comparison is there because assigning the hash it already holds fires no `hashchange` at all, so re-reading it would be a no-op on exactly the second ticket opened.

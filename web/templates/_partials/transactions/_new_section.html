{# Body of the Transactions area's "New transaction" section. One HTMX host holding either the MD-1 chooser or an open composer. The host is what makes web/routes/areas.py a no-DB shell render: the area page ships the chooser as static markup, and the first database read happens when a tile is clicked. The host also answers Q-UX-A-5. Since P-UX-A0b an area shows one section at a time, so a composer swapped in from the Blotter — the ticket-number button targets this host — would otherwise open out of sight. The handler below moves the fragment to `new`, and `shell.js` does the rest on `hashchange`: the shell stays the only thing that touches `hidden`, and no new script file is needed. Two guards, both load-bearing. `event.detail.target === this` is there because `htmx:afterSwap` bubbles and every recalculation swaps `#tx-derived` *inside* this host — only a swap of the host itself is a change of surface. The fragment comparison is there because assigning the hash it already holds fires no `hashchange` at all, so re-reading it would be a no-op on exactly the second ticket opened. The host carries no class since P-UX-A1e2. `.tx-new` set a flex column with a gap, and the host holds exactly one visible child — the chooser, a composer's `pf-form`, or a confirmation's `pf-form__main`, each of which brings its own column — so the rule had nothing to space. The id stays: it is what the composer targets and what the negative-cash indicator listens to. Context: none (the chooser is static). #}

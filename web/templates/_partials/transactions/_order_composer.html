{# M-1 order composer — U-BUY / U-SELL against an instrument already on the book (ADR-0128, S4a). Swapped into #tx-composer-host by the chooser's live tile; Discard swaps the chooser back. The form is the unit of state. Every field posts to POST /api/transactions/recalc on input or change — `submit` is in the trigger list too, so a stray Enter recalculates rather than navigating away — and the response re-renders the four derived regions — the ticket title, the context strip, the amounts/settlement rail and the messages/actions panel. The static half (the picker, the Execution inputs, the Provenance fields) is never re-rendered, so nothing the user is typing into moves under them. Anatomy is §2.5's, since P-UX-A1b: one stable form column (`pf-form__main`), the derived figures in a sticky summary rail placed by CSS grid (§2.5.3), and the outcome in a sticky action bar with one primary (§2.3.4, R1, R3). The head is a crumb (§2.1.6). A composer is a sub-surface of the New transaction section, so it renames the section's own `

` out of band rather than drawing a second heading of its own: `areas/_section.html` already gives that element `id="new-title"`, which is also what the section's `aria-labelledby` points at, so the crumb inherits the accessible name without the shell changing. `_order_title.html` keeps its id and its own out-of-band swap, and lands here inside the crumb's `__here` slot. MD-2 puts ticket persistence on the first explicit gesture, so the head's stamp reads "New ticket · Unsaved" until one of the three fires, and flips to "Ticket #n" plus the status pill afterwards. `ticket_id` then rides in a hidden field, which is how the next gesture knows to update this row instead of allocating a second number. The stamp goes to the head's as-of slot — the mock puts it in the view head, and P-UX-A1a already built that out-of-band seam for the Blotter's stamp. The gesture buttons post the whole form (`hx-include="closest form"`) and replace the composer with the server's answer — a re-render, or, for a booking, the MD-16 confirmation panel. The static inputs therefore carry their posted values: after a save the form shows what was saved, rather than emptying itself under the user. Context: csrf_token, investments (the picker set), cases (open cases), trade_date, entered (the raw posted strings), case_id, ticket_id, ticket_number, ticket_status, error, plus everything `_derived_context` returns. #} {% include "_partials/transactions/_composer_head.html" %}

{# What a reversal undid (A-15). Heads the re-rendered History list rather than landing in a slot of its own: the reversal changed the row it was about, so the list is re-fetched either way, and a report swapped into a row of a list that is itself being replaced would be swapped into a detached node. The per-type tally always states all four types, zeros included. A zero is a fact the reader can rely on; an omitted line is one they have to interpret. `retained_because` is the service's own sentence, verbatim (A-4 / A-5) — it names the child table that kept the row, which is the only thing that tells the operator what to clear if they want it gone. P-UX-A1e put it on `pf-note`, the one note pattern (§2.6.2). The wrapper went with the move: `.pf-note + .pf-note` spaces the pair, which is all the retired `tx-messages` supplied. Both notes take the **info** tone — the record names three, and none of them is a "done": a completed reversal is stated, not celebrated, and the check glyph carries the completion the tone cannot. Registered as a flag for the record. Context: report — ticket_number, reason, count, by_type, shell. #}

{# The tenant calibration editor (ADR-0116 §7), rendered inside the Watch points view's Advanced tuning disclosure. Follows the Back-Office SAA configuration pattern: editable fields, an explicit save bar with dirty state, server-validated on POST. Three rules are load-bearing here: * Every field shows its **effective** value — defaults ⊕ this tenant's revision — and carries a separate default / customised marker taken from the stored row. Never render a blank for "not overridden": the operator must see what the beat would actually run on. The one exception is the "WARN per family" group (ADR-0133 §3.4): a NULL family column inherits the WARN default on this same form, so blank means inherit, the placeholder shows the inherited value and the marker reads "inherits". An always-effective field there would freeze every inheriting family at the old default on the next save. * The form posts the complete desired configuration, defaults included. Reducing it back to deviations (so a field returned to its default is stored as NULL again) belongs to `save_calibration_revision`; this template and its script must never reimplement that, or the two would drift. * The pinned invariants are not editable. `fund_closure` renders as a locked row with **no input at all** — not submittable, rather than an input that is merely styled as disabled — and the three coupling rules render as constraint hints on the fields they bind. The write path enforces all four regardless of what this renders. Every number is a text field (R10): the two band boundaries take `inputmode="numeric"` (integers 1–9), every other figure `inputmode="decimal"`; the route parses and refuses verbatim. The save bar is the form's pf-actionbar (D-A6-68). Context (via _calibration_context): csrf_token, calibration_saved, calibration_error, warn_default, band_boundaries, options_gate, family_warns, floors, caps, deltas, pinned, notes. #}

{# Per-subject sensitivity editor (ADR-0116 §3, §6) — the inline drawer the monitor's "Adjust sensitivity" button opens. The overlay half of the asymmetry: this form adjusts *how nervously* a derived subject is watched and nothing else. There is no ceiling field and no subject field, because a ceiling belongs to the limit set alone — the schema's per-family CHECKs refuse them, so no bug here can grow a second edit point for limits. An `rss` subject offers **mute only**: a press cluster is non-scalar, so a WARN threshold and a re-trigger delta would have nothing to measure, and the repository and the schema both refuse them. A rejected save swaps the drawer for the Watch Desk's inline-error partial instead of re-rendering this form, so there is no error slot here — one inline-error idiom for the whole section. The drawer opens from two surfaces since ADR-0116 §7 — the monitor row and the Calibration watchpoint list — so its swap target is passed in rather than hardcoded. One editor, two containers; the alternative was a second editor, which is how two surfaces start disagreeing about what a subject is set to. Since P-UX-A6-a2 the drawer is the slot-panel idiom of transactions/_cancel_panel.html: `pf-panel` with its head, the fields as `pf-field--half` in a `pf-grid`, and Save and Keep in `pf-panel__foot`. Save is a default button — the view's one primary is "Check now" (R1). Keep empties the form's own parent, which is the slot cell on the monitor and on the Watch points list alike (D-A6-48, D-A6-50). The subject key may be printed here: the drawer is the subject's own disclosure.

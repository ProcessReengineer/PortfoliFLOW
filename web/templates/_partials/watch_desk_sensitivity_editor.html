{# Per-subject sensitivity editor (ADR-0116 §3, §6) — the inline drawer the monitor's "Adjust sensitivity" button opens. The overlay half of the asymmetry: this form adjusts *how nervously* a derived subject is watched and nothing else. There is no ceiling field and no subject field, because a ceiling belongs to the limit set alone — the schema's per-family CHECKs refuse them, so no bug here can grow a second edit point for limits. An `rss` subject offers **mute only**: a press cluster is non-scalar, so a WARN threshold and a re-trigger delta would have nothing to measure, and the repository and the schema both refuse them. A rejected save swaps the drawer for the Watch Desk's inline-error partial instead of re-rendering this form, so there is no error slot here — one inline-error idiom for the whole section. The drawer opens from two surfaces since ADR-0116 §7 — the monitor row and the Calibration watchpoint list — so its swap target is passed in rather than hardcoded. One editor, two containers; the alternative was a second editor, which is how two surfaces start disagreeing about what a subject is set to. Context: csrf_token, subject_key, family, scalar, editor_id, muted, mute_locked, warn_threshold_pct, re_trigger_delta, notes, warn_default_pct, delta_default, return_to, target. #}

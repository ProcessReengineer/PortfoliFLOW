{# Add / edit form for one defined signal watchpoint (ADR-0116 §6, §7). One template, two modes. In **edit** mode the identity — the instrument or the currency pair — renders as a read-only fact, not an input: changing what a watchpoint watches makes it a different watchpoint, so that is a create plus a retire, and `WatchpointRepository.revise` inherits those columns rather than accepting them. Offering an input the write path ignores would be a lie in a form. The defined half of the ADR-0116 §3 asymmetry lives here: this form offers a threshold and a window because for these families the watchpoint *is* the subject. The overlay families' drawer (watch_desk_sensitivity_editor.html) offers neither, and the schema's per-family CHECKs refuse them under it. Every value is pre-filled from the current version, because a revision states the **complete** calibration — an immutable version row is meant to be readable on its own, without replaying its predecessors. Bounds are not enforced here. The `min`/`step` attributes are a convenience for the operator's keyboard, never the rule: positivity, the WARN band and the pair format are the repository's contract (ADR-0116 §3) and a refusal renders inline through the section's one error idiom.

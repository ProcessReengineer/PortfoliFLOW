{# Add / edit form for one defined signal watchpoint (ADR-0116 §6, §7). One template, two modes. In **edit** mode the identity — the instrument or the currency pair — renders as a read-only fact, not an input: changing what a watchpoint watches makes it a different watchpoint, so that is a create plus a retire, and `WatchpointRepository.revise` inherits those columns rather than accepting them. Offering an input the write path ignores would be a lie in a form. The defined half of the ADR-0116 §3 asymmetry lives here: this form offers a threshold and a window because for these families the watchpoint *is* the subject. The overlay families' drawer (watch_desk_sensitivity_editor.html) offers neither, and the schema's per-family CHECKs refuse them under it. Every value is pre-filled from the current version, because a revision states the **complete** calibration — an immutable version row is meant to be readable on its own, without replaying its predecessors. Bounds are not enforced here, and since P-UX-A6-a2 the generated parameter fields are text inputs, not native number fields (R10): the route parses what was typed, and positivity, the WARN band and the pair format are the repository's contract (ADR-0116 §3). A refusal renders inline through the section's one error idiom, without an echo of the value as read (Q-UX-S-A6-13). The frame is the drawer's (watch_desk_sensitivity_editor.html): a `pf-panel` with its head, the fields as `pf-field--half` in a `pf-grid`, and Save and Keep in `pf-panel__foot`. Keep empties the form's own parent — the editor slot cell on the monitor and the list, or `#dc-watchpoint-new` for a new watchpoint (D-A6-50).

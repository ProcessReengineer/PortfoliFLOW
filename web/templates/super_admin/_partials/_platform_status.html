The scheduler runs inside this web process and asks every interval which tenants are due. Per-tenant rhythms are unaffected by it — those stay in each tenant's own cadence settings. Configured by TICK_SCHEDULER_ENABLED and TICK_SCHEDULER_INTERVAL_SECONDS in the deployment environment, deliberately not editable here (ADR-0117 §4).

{% else %}

No scheduler is running inside this web process, so an external tick source — a systemd timer, cron, or equivalent running portfoliflow irene-tick and portfoliflow market-data-tick — is expected. Without one, no tenant is ever due-checked and scheduled work never runs. If you expected the built-in scheduler here, check that TICK_SCHEDULER_ENABLED is true and that the deployment has a superuser database URL, then restart — the startup log names whichever of the two kept it down (ADR-0117 §4). Running both sources at once is safe.
